# lunarbase-pmm-math

[![CI](https://github.com/Lunarbase-Lab/lunarbase-pmm-math/actions/workflows/ci.yml/badge.svg)](https://github.com/Lunarbase-Lab/lunarbase-pmm-math/actions/workflows/ci.yml)
[![License: MIT OR Apache-2.0](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue)](#license)

Bit-exact Rust, Go, and Node.js implementations of the current LunarBase Pool
math: linear anchor quotes plus immediate directional punishment. Shared JSONL
vectors are generated by the Solidity implementation and replayed by every
package.

## State and quote model

`sqrtPriceX96` is the operator anchor `uint160`. Fees and punishment are
Q24 `uint24` values; `0xffffff` is the storage sentinel for conceptual
`2^24` (100%).

```text
PoolParams {
    sqrt_price_x96,         // uint160, Q64.96 anchor
    fee_ask_x24,            // uint24, current Y -> X fee
    fee_bid_x24,            // uint24, current X -> Y fee
    reserve_x, reserve_y,   // uint112 active reserves
    max_punishment_x24,     // uint24; 0xffffff means conceptual 100%
}
```

The exact-input quote is linear at the squared anchor. Solidity rounds down at
both `mulDiv` steps, and each implementation preserves those two operations:

```text
X -> Y gross = floor(floor(amountIn * anchor / Q96) * anchor / Q96)
Y -> X gross = floor(floor(amountIn * Q96 / anchor) * Q96 / anchor)
```

The current swap first computes its punishment from the pre-swap active
reserves. That increment is saturating-added to the stored bid or ask fee, and
the resulting effective fee is deducted from the triggering output:

```text
inventoryWealth = valueXInY(reserveX, anchor) + reserveY
swapWealth      = valueXInY(amountIn, anchor)       // X -> Y
swapWealth      = amountIn                         // Y -> X
desired         = ceil(maxPunishment * min(swapWealth, inventoryWealth)
                       / inventoryWealth)
effective       = min(currentDirectionalFee + desired, 0xffffff)
applied         = effective - currentDirectionalFee  // only on success
```

`effectiveFeeX24` is returned by every off-chain quote before the caller fee
multiplier. A successful swap persists it. `SwapImpossible`, reserve overflow,
or any later transaction revert leaves the stored fees and reserves unchanged.

Quote functions are stateless: repeatedly quoting chunks against the same
`PoolParams` does not model sequential swaps. To evaluate a split execution,
feed each successful simulation's effective fees and reserves into the next
chunk (or use the mutable Go simulation API). This distinction is economically
material because the current mechanism permits a larger aggregate output when
one order is split across successful swaps.

`upd(anchor, ask, bid)` atomically publishes a new quote epoch and replaces
both accumulated directional fees. `sqrtPriceNext` remains in the API for
Solidity ABI compatibility and always equals the anchor.

## API

Names follow language conventions:

| Operation | Rust | Go | Node.js |
| --- | --- | --- | --- |
| Quote X -> Y | `quote_x_to_y` | `QuoteXToY` | `quoteXToY` |
| Quote Y -> X | `quote_y_to_x` | `QuoteYToX` | `quoteYToX` |
| Quote with caller multiplier | `*_with_multiplier` | `*WithMultiplier` | `feeMultiplier` field |
| Simulate standard-token X -> Y | `simulate_successful_swap(..., Direction::XToY, ...)` | `SimulateStandardTokenSwap(..., DirectionXToY)` | `simulateXToY` |
| Simulate standard-token Y -> X | same with `YToX` | same with `DirectionYToX` | `simulateYToX` |

Rust and Node simulations return the triggering quote (including
`effectiveFeeX24`), desired/applied punishment, committed directional fees and
reserves. Go returns a `SwapSimulationResult` for applied swaps and modeled
rollback outcomes, and mutates `PoolParams` only when the standard-token
transition commits. Arithmetic and invalid-domain failures remain Go errors;
an applied Go result can be restored with `MarkRolledBack` if a later transfer
or accounting step fails.

Node.js carries `uint112`, `uint160`, and `uint256` values as strict
decimal or `0x`-hex strings. Q24 values are JavaScript numbers and are
validated as finite integers before native conversion.

## Build and parity tests

```sh
make
make ci
make bench
./scripts/regenerate-vectors.sh ../dark_pools
```

The vector generator runs the Solidity oracle, replaces both JSONL corpora,
then Rust, Go, and Node.js replay every row. Tests compare quote output,
`pNext`, fee, `effectiveFeeX24`, executability, punishment, directional fees, and reserves
exactly—no numeric tolerance.

Requirements: Rust 1.90+, Go 1.22+, and Node.js 18+.
